# Публикация прототипа

Подготовлен вручную запускаемый workflow `.github/workflows/pages.yml` для публикации статической сборки на GitHub Pages. Создание этого файла и отправка коммита не публикуют сайт; для публикации нужен отдельный запуск workflow после разрешения пользователя.

Пользователь разрешил загрузку исходников и архива в публичный `webtkach/test`. Архив для скачивания находится в `downloads/lapki.zip`. Отдельная публикация сайта GitHub Pages не выполнялась и требует отдельного разрешения; доступность Pages для закрытого репозитория зависит от плана GitHub.

После разрешённой отправки исходников:

1. В `webtkach/test` открыть Settings → Pages и выбрать Source: GitHub Actions. Автоматически включить Pages в текущем чате нельзя: проверенные read-only запросы к GitHub API вернули Forbidden, хотя чтение репозитория через Git работает.
2. Если первая сборка выполнялась до включения Pages, запустить workflow `Publish Lapki to GitHub Pages` заново через Actions → Run workflow.
3. Дождаться успешного задания deploy. Использовать URL из `deployment.outputs.page_url`, не выдавать предполагаемый адрес за работающий.
4. Проверить сайт браузерным сценарием: `APP_URL=<подтверждённый URL> npm run test:e2e`.

Встроенный визуализатор и ссылки на `/workspace/...` в чате не обеспечивают скачивание файлов из облачной среды. Автономный архив существует в `artifacts/lapki.zip`, но механизма его загрузки во вложения этого чата среди доступных инструментов нет. Не повторять такие ссылки как способ доставки.

Для размещения в подкаталоге используется `npm run build -- --base=./`. Эта настройка требуется для JS/CSS; пути к фотографиям также учитывают Vite BASE_URL в приложении. Публикация не подключает автоматический поиск Instagram и генерацию ИИ.
